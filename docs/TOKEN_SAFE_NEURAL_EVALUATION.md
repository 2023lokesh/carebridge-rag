# Token-safe neural indexing and private development evaluation

**Purpose:** Fix actual MiniLM token truncation, build both chunking strategies from the **same** archived CDC crawl, evaluate only the **frozen 24 development questions**, and preserve all 16 sealed test questions.

## Provenance

- Archived CDC crawl: [Actions run 38016315533](https://github.com/2023lokesh/carebridge-rag/actions/runs/38016315533), 163 normalized pages, 35 PDFs, 13 table pages.
- First fixed index: 3,262 original chunks, including **174** over the 256-token model limit. These may be truncated at embedding time; avoid using it as the final neural index.
- `data/frozen_split_manifest.json` documents 24 development IDs, 16 sealed test IDs, hashes and the origin/verification provenance. **Neither full question text nor held-out test answers are committed to this public repository.**

## Build without truncation

`.github/workflows/token-safe-index-compare.yml` uses the archived corpus, actual `all-MiniLM-L6-v2` fast-tokenizer WordPiece offsets, 24-token overlap on oversized windows, and a two-token safety margin beyond special tokens. Each output chunk preserves the original source characters; the build fails if **any** output chunk exceeds `model.max_seq_length`. It writes separate Chroma databases for fixed (180/30 words) and heading-aware chunks, ensuring identical source SHA-256 and zero missing/orphan IDs. No second web crawl is performed.

The workflow automatically runs on pushes to `course/token-safe-heading-evaluation`, and can also be dispatched manually after merging. Download the `carebridge-token-safe-indexes-<run-id>` artifact for comparison and local experiments. Preserve the index artifact before its seven-day retention expiry.

## Private development-only metrics (do not push dev/test answers to GitHub)

Save the `dev_24.jsonl` from the original private frozen set package locally. Unzip the new indexing artifact into the project root, then:

```bash
pip install -r requirements-full.txt
python -m scripts.eval_dev_retrieval --baseline B1 --dev PRIVATE_PATH/dev_24.jsonl --db-dir data/chroma_fixed_v2 --output reports/dev_private/b1.json
python -m scripts.eval_dev_retrieval --baseline B2 --dev PRIVATE_PATH/dev_24.jsonl --db-dir data/chroma_fixed_v2 --output reports/dev_private/b2.json
python -m scripts.eval_dev_retrieval --baseline B3 --dev PRIVATE_PATH/dev_24.jsonl --db-dir data/chroma_heading_v2 --output reports/dev_private/b3.json
```

These are *retrieval-only*, source-URL-labelled metrics for **18 of the 24 development questions** that have relevant source URLs. Five unanswerables and one adversarial-without-URL question need a separate refusal experiment. B3 uses fusion of BM25 and dense rank lists (RRF) over heading-aware chunks, then true neural cross-encoder reranking of a 20-candidate pool and top-five results. Results are not answer correctness, citation verification, generation latency or costs. B0 remains a separately required closed-book generation experiment.

For paired retrieval improvement on real development questions, pair the same question IDs in the two JSON result files and run `bootstrap_paired` from `scripts/eval_dev_retrieval.py`. Quantify reranker quality and overhead separately by adding a no-rerank ablation; never label the small demo's TF-IDF proxy as neural B2/B3.

### Preliminary BM25 result before token-budget fix

On the **original** 3,262-chunk fixed index (not the corrected index), 18 URL-labelled dev questions yielded Recall@5 **0.6944**, Recall@20 **0.9444**, MRR **0.5894**, nDCG@10 **0.6300**, p50 **78.03 ms**, p95 **153.96 ms** (machine-specific, no model load). The corrected-index B1/B2/B3 run must replace these as the principal comparison; do not infer an improvement from unpaired or noncomparable settings.
